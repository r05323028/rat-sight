# Design

## Source and classification

Use the source candidate recorded by Evidence ID `EVID-TPE-DISTRICT-BOUNDARIES-2026-10-15`: Taipei City Government Department of Civil Affairs, dataset 121199, resource `臺北市區界圖_20220915`, SHP archive, source CRS EPSG:3826. The evidence record includes the retrieval/hash/archive/inspection commands and output. The geometry is an official administrative reference layer, not rodent observation data. Persist `data_class=ADMINISTRATIVE_REFERENCE` separately from the existing epistemic `classification`; use `classification=UNVERIFIED` because currentness after the 2022-09-15 resource version is unresolved. This value must not be presented as a rodent observation, inferred connectivity, or simulation.

## Persistence

Add a dedicated `administrative_districts` table rather than overloading the generic spatial-artifact table. Store a stable district identifier, name, `data_class`, epistemic `classification`, geometry in EPSG:4326, and a required versioned provenance object. The provenance object has this exact JSON shape: `schema_version` (string, currently `1`), `source_url` (string URI), `dataset_id` (non-empty string), `resource_version` (non-empty string), `retrieved_at` (RFC3339 UTC string ending `Z`), `archive_sha256` (lowercase 64-hex SHA-256 string), `license` (non-empty string), `attribution` (non-empty string), `source_crs` (literal `EPSG:3826`), `target_crs` (literal `EPSG:4326`), `processing` (object with non-empty `tool`, `tool_version`, and ordered non-empty `steps` array), and `uncertainty` (object with non-empty `currentness` and `note`). The canonical provenance copy is stored per row and serialized once at the GeoJSON response top level; feature properties include district identity, data class/classification, and `provenance_schema_version` plus source/version/hash references. Feature properties do not duplicate the full object; clients MUST resolve complete provenance from the top-level object. All provenance is immutable for a source version. Use a unique constraint on `(dataset_id, resource_version, district_id)` and reject a different archive hash for an existing dataset/resource version. Add a GiST index for the polygon query path. The migration is additive and does not reset or delete unrelated data.

## Import boundary

Implement a small dataset-specific importer under the API/application boundary, using existing geo/CRS utilities where practical. The import command accepts the source archive (not an extracted directory); a separate verification command may inspect extracted files but cannot import them without the archive hash. It checks the expected shapefile components and parses a non-ambiguous `.prj` as EPSG:3826 with explicit axis order, validates finite non-empty Polygon/MultiPolygon geometry before and after transformation to EPSG:4326, rejects unsupported dimensions/types and does not silently repair invalid geometry. Source coordinates MUST remain within the documented EPSG:3826 envelope `[296000, 2761000, 317500, 2790000]`; transformed coordinates MUST remain within `[121.45, 24.94, 121.70, 25.23]` EPSG:4326. These envelopes are a deterministic 1 km/source and approximately 0.01 degree/consumer margin around the observed source bounds, used to catch axis/CRS mistakes, not to assert district count. Required fields are `CPID` (decode UTF-8, Unicode NFC normalize, trim surrounding whitespace, reject empty/duplicate normalized values) and `TNAME` (decode UTF-8, Unicode NFC normalize, trim surrounding whitespace, reject empty values). It uses one transaction for all rows: same source version and hash upserts changed rows; a different hash for an existing dataset/resource version fails closed and requires a new resource version; an omitted identifier fails and rolls back rather than deleting prior rows. The command is documented and does not download live data implicitly; tests use a small deterministic fixture plus malformed CRS/geometry/hash fixtures.

## API and web

Expose `GET /api/v1/administrative-districts` as a small GeoJSON FeatureCollection contract. The response envelope contains `type`, `features`, `data_state` (`empty` or `available`), `data_class=ADMINISTRATIVE_REFERENCE`, and `provenance` when available. Empty storage yields HTTP 200 with zero features and `data_state=empty`; storage failure yields a non-2xx error and never an empty success. Persisted malformed geometry/provenance is an explicit server error. Each feature contains `district_id`, `district_name`, `data_class`, `classification`, and the complete immutable provenance object. The dashboard fetches this endpoint separately from the existing layer catalog, adds one administrative-reference toggle, and attaches a click handler to show district name and source. Existing simulation source/layer remains independent.

## Risks and limits

The resource label is dated 2022-09-15 and current legal currency is not established; this limitation is visible in provenance and documentation. CRS correctness is tested from the fixture's `.prj` and transformation bounds. No expected district count is hardcoded into reusable ingestion logic. No live government download is used by ordinary unit tests.
