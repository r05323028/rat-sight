## Contract

The backend is authoritative. `GET /api/v1/stormwater-pipelines` returns a GeoJSON FeatureCollection in EPSG:4326 with `data_state` (`empty`/`available`), `data_class=INFRASTRUCTURE_REFERENCE`, top-level typed `StormwaterProvenanceV1`, and feature properties containing the unique normalized source `識別碼` as opaque API `segment_id` (backed by persistence `source_record_id`), nullable `管線編號`, a bounded allowlist of source attributes, `classification=UNVERIFIED`, dataset/version/hash references, and no inferred topology. `StormwaterProvenanceV1` is owned by the backend and has exactly these top-level keys: `schema_version`, `source_url`, `download_url`, `dataset_id`, `resource_id`, `resource_version`, `retrieved_at`, `archive_sha256`, `license`, `attribution`, `source_crs`, `target_crs`, `z_handling`, `processing`, `source_quality`, and `uncertainty`; `z_handling` is the literal `"dropped"` for this resource because its vertical datum is undocumented; `processing` contains `tool`, `tool_version`, and `steps`; `source_quality` contains `reference_only`, `missing_pipe_number_count`, `duplicate_pipe_number_value_count`, `missing_start_endpoint_count`, `missing_end_endpoint_count`, and `missing_notes_count`; `uncertainty` contains `currentness` and `note`. The backend owns this immutable envelope and the frontend consumes it without reinterpretation. Provenance includes source/download URLs, license/attribution, source/target CRS, processing, publisher reference-only warning, and data-quality limitations. A bounded `bbox=minX,minY,maxX,maxY` query is supported because the source has approximately 20k line features; coordinates are EPSG:4326 and the query is bounded/validated.

## Persistence/import

Use a dedicated additive `stormwater_pipelines` table and explicit GiST index. The importer accepts a local XML source file only (no live download), verifies SHA-256 and the expected dataset/version, parses selected GML-like `UTL_管線` records, requires a unique non-empty normalized `識別碼` per source record, requires EPSG:3826, rejects malformed/unsupported/non-finite/invalid lines, drops unknown Z values to 2D EPSG:4326 while recording that the source vertical datum is unresolved, preserves nullable source fields, and transactionally upserts by `(dataset_id, resource_version, source_record_id)`. The content hash is compared on re-import: changed content for an existing source key fails closed; omitted source records fail closed rather than deleting. Duplicate or missing `管線編號` values are retained as non-key attributes; no rows are silently merged or interpreted as connected.

## Frontend

Reuse the administrative layer lifecycle in `MapView`, adding a separate stormwater source and line layer. The dashboard requests the current MapLibre viewport bbox on initial map load and on debounced `moveend` events rather than an unbounded collection. The backend cap of 5,000 is a safety net; when `truncated=true`, the dashboard says the view is partial and asks the user to zoom in. The public feature-property allowlist is exactly: `segment_id` (non-empty opaque string; persistence-only `source_record_id` is not exposed), `category_code`, `pipe_number`, `start_node_id`, `end_node_id`, `managing_unit`, `work_category`, `installation_date`, `dimension_unit`, `diameter_width`, `diameter_height`, `conduit_count`, `material`, `start_burial_depth`, `end_burial_depth`, `length`, `pipe_type`, `use_status`, `data_status`, and `notes` (all nullable strings preserving source lexical values). Nulls are rendered as `Unavailable`. The dashboard has an independent toggle and inspection panel. Stormwater styling and legend text explicitly identify infrastructure reference data and never share the simulation layer. Existing administrative and simulation controls remain independent. `start_node_id` and `end_node_id` are displayed as publisher attributes only and are explicitly labeled as not verified connectivity.

## Verification

Synthetic fixtures cover deterministic importer/API/UI behavior. A real isolated browser smoke uses a deterministic seeded stormwater fixture through production persistence functions and calls the running FastAPI endpoint without application API interception. A one-time `scripts/verify_official_districts.sh` check downloads the documented archive to a temporary path, verifies SHA-256, starts an isolated disposable PostGIS stack, applies migrations, runs the existing importer, checks the expected district identity set and API response, starts the dashboard with the imported dataset, and runs `apps/web/e2e/official-district.spec.ts`; it records results in the OpenSpec QA artifact, is not part of regular tests, and cleans all temporary state. Official stormwater bytes are likewise not committed.
